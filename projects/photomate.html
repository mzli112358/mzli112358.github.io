PhotoMate

会说话的拍照机器人服务

A Conversational Robot Photography Service

面向展会、景区、毕业典礼与商场的具身智能摄影师：发现走近的客人，用语音聊天询问要不要拍照，引导姿势，自动快门，让客人看片决定是否重拍，再生成二维码带走照片。产品灵魂是「有情绪价值的 AI 摄影师」——会搭话、会夸奖、会引导，而不是只会按快门的机器。

An embodied photographer for exhibitions, scenic spots, graduations, and malls: detects approaching guests, invites them by voice, guides posing, captures automatically, lets them review/retake, then delivers photos via QR code. The soul is emotional AI photography—not a mute shutter machine.

Concept

不是自拍亭，而是主动服务的摄影师

Not a Photo Booth—an Active Photographer

把移动、感知、语音交互、拍摄与交付组合成一段完整体验；核心编排不绑定单一本体。

Combines mobility, perception, voice interaction, capture, and delivery into one experience; orchestration is embodiment-agnostic.

01

主动发现

Active Discovery

镜头持续寻人，发现靠近、停留、面向机器人的客人后，建立语音会话并邀请拍照。

Continuously searches for people; when a guest approaches and faces the robot, starts a voice session and invites a photo.

02

专业引导

Guided Capture

语音询问意愿、设备与模式；结合实时画面引导站位与姿势，达标后自动快门。

Asks intent, device, and mode; guides pose with the live view, then fires the shutter when ready.

03

即时交付

Instant Delivery

屏幕复核成片，支持重拍；后端给出稳定 photo_url，可选上传 Supabase，前端展示二维码扫码带走 JPEG。

On-screen review with retake; backend issues a stable photo_url (optional Supabase upload); frontend shows a QR for JPEG download.

Experience Flow

一次服务：S0 → S6

One Session: S0 → S6

代码状态枚举为 S0→S1→S2→S3→S5→S6→S0（产品文档里的「S4 拍照质检」合入 S3 内完成）。前端 /flow/ 经 SSE 跟随后端状态自动切页，客人无需点「下一步」。

Code states: S0→S1→S2→S3→S5→S6→S0 (product-doc “S4 capture/QC” is folded into S3). The /flow/ frontend follows backend state over SSE—no manual “next”.

Architecture

五层架构 + AI / 状态机分工

Five Layers + AI / FSM Split

Qwen-Omni 负责听、说、看与意图；本地 FSM 负责阶段、超时、重试与硬件释放。AI 只能通过 Function Calling「按按钮」推进流程。

Qwen-Omni handles listen/speak/see/intent; the local FSM owns stages, timeouts, retries, and resource release. The model advances only via function calls.

① 体验层① Experience外接屏浏览器 kiosk · 语音 · 打卡立牌 · 手机扫码Kiosk screen · voice · check-in sign · phone QR
② 展示层② PresentationReact + Vite /flow/（TanStack）：寻人 / 设备 / 模式 / 取景 / 复核 / 分享；另有 /photo-agent 调试台React + Vite /flow/ (TanStack): search / device / mode / preview / review / share; plus /photo-agent test console
③ 编排层③ OrchestrationPython FastAPI：显式 asyncio FSM · SessionContext · 工具分发 · 本地照片 APIPython FastAPI: explicit asyncio FSM · SessionContext · tool dispatch · local photo API
④ 设备层④ Devices本机相机 / 麦克风 / 扬声器 · AEC · Insta360 / Galbot adapter 预留Local camera / mic / speaker · AEC · Insta360 / Galbot adapters reserved
⑤ 云端层⑤ CloudDashScope Qwen-Omni Realtime · 可选 Supabase 对象存储 · segno 二维码DashScope Qwen-Omni Realtime · optional Supabase storage · segno QR

三条并行管道

Three Parallel Pipelines

  • 音频管：麦克风 → AEC → Omni → 扬声器
  • 视频管：相机 → Omni「看」+ 前端 MJPEG
  • 状态管：FSM → SSE → 前端自动切路由
  • Audio: mic → AEC → Omni → speaker
  • Video: camera → Omni vision + MJPEG preview
  • State: FSM → SSE → frontend auto-routing

AI 可调用的「按钮」

  • report_pose_turn / report_pose_readiness / capture_photo
  • report_review_intent（保存 → S6；重拍 → 回 S3）
  • report_review_intent (keep → S6; retake → S3)

Previous Attempt

为何探月未完成真机闭环

Why the Real-Robot Loop Was Not Closed

事实口径（不再反复确认） Fact statement (do not re-ask)

PhotoMate 在探月计划 · Physical AI 黑客松期间未完成完整真机 Demo。直接原因是赞助商本体未向参赛项目开放导航、机械臂/灵巧手等执行权限，感知—交互—拍摄软件链无法接到真实机器人动作上。

During the Tanyue Physical AI Hackathon, PhotoMate did not finish a full real-robot demo. The sponsor platform did not expose navigation / arm / dexterous-hand execution APIs, so the perception–interaction–capture software could not close on real robot actions.

当时实际沉淀：产品与流程设计、五层软件架构、app/photo_agent/ 状态机与 adapter、React /flow/ 与调试台、本机设备与 Omni 联调、部署文档与部分硬件/外设方案。文档里完整「巡航→点快门→递照片」多为设计目标，不能表述为已全部完成。

What shipped: product/flow design, five-layer software, app/photo_agent/ FSM + adapters, React /flow/ + test console, local device + Omni integration, deployment docs, partial hardware plans. Full “cruise → shutter tap → hand photo” was mostly a design target, not completed delivery.

方案按「能力接口—任务状态—本体适配」设计，不依赖银河通用。星尘 Astribot OS 适合把同一体验做成可运行 App / 半解决方案。

The design is capability-interface / task-state / embodiment-adapter based—not Galbot-locked. Astribot OS fits turning the same experience into a runnable App / semi-solution.
