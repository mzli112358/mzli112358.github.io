PhotoMate

会说话的拍照机器人服务

面向展会、景区、毕业典礼与商场的具身智能摄影师：发现走近的客人，用语音聊天询问要不要拍照，引导姿势，自动快门，让客人看片决定是否重拍，再生成二维码带走照片。产品灵魂是「有情绪价值的 AI 摄影师」——会搭话、会夸奖、会引导，而不是只会按快门的机器。

Concept

不是自拍亭，而是主动服务的摄影师

把移动、感知、语音交互、拍摄与交付组合成一段完整体验；核心编排不绑定单一本体。

01

主动发现

镜头持续寻人，发现靠近、停留、面向机器人的客人后，建立语音会话并邀请拍照。

02

专业引导

语音询问意愿、设备与模式；结合实时画面引导站位与姿势，达标后自动快门。

03

即时交付

屏幕复核成片，支持重拍；上传云端并生成二维码，客人扫码带走 JPEG。

Experience Flow

一次服务：S0 → S6

探月 MVP 把流程拆成显式状态；前端 `/flow/` 按后端状态自动切页，客人无需点「下一步」。

S0 · 待机系统空闲，等待开始一轮服务
S1 · 寻人实时画面寻人；发现后进入邀请
S2 · 询问要不要拍 → 选设备 → 选模式
S3 · 取景语音引导站位/姿势，自动快门
S5 · 复核看成片：保存或再来一张
S6 · 交付二维码下载；约 60 秒后下一轮
Architecture

五层架构 + AI / 状态机分工

Qwen-Omni 负责听、说、看与意图；本地 FSM 负责阶段、超时、重试与硬件释放。AI 只能通过 Function Calling「按按钮」推进流程。

① 体验层外接屏浏览器 kiosk · 语音 · 打卡立牌 · 手机扫码
② 展示层React + Vite 前端 `/flow/`：寻人 / 选设备 / 选模式 / 取景 / 复核 / 分享
③ 编排层Python FastAPI：会话服务 · PhotoAgent Runtime · FSM · 工具分发 · 拍照/上传/二维码 API
④ 设备层相机 · 麦克风 · 扬声器 · AEC 回声消除 · Insta360（UVC）适配
⑤ 云端层阿里云百炼 Qwen-Omni Realtime · Supabase Storage（预留打印机 API）

三条并行管道

  • 音频管：麦克风 → AEC → Omni → 扬声器
  • 视频管：相机 → Omni「看」+ 前端 MJPEG 预览
  • 状态管：FSM → SSE → 前端自动切路由

AI 可调用的「按钮」

  • `report_photo_intent` / `report_capture_device` / `report_capture_mode`
  • `report_pose_turn` / `report_pose_readiness` / `capture_photo`
  • `report_review_intent`（保存 → S6；重拍 → 回 S3）
What We Built

探月黑客松实际做到了什么

依据仓库 PhotoMate-Moonbot-Hackthon 与完成审计：软件编排链可跑；本体执行层未开放权限，真机闭环未完成。

模块 状态 证据 / 说明
S1–S6 显式状态机 + Runtime 已完成 `app/photo_agent/`：asyncio FSM、会话服务、工具分发、可观察 JSON 日志；pytest 全量覆盖
Qwen-Omni 实时语音多模态 已完成 真实麦克风/扬声器 + Function Calling；分状态与 mock/local-real 模式可跑
前端服务流 `/flow/` 已完成 React 页面：search / device / mode / preview / review / post；SSE 驱动自动切页
设备适配与交付 部分完成 本机相机/音频 smoke、AEC、本地照片 API；Supabase 上传与二维码；Insta360 UVC 路线
导航 / 机械臂 / 灵巧手点快门 未闭环 方案与部分 Dashboard/SDK 预留存在，但现场本体未开放执行权限，无法接入关键动作
完整真机 Demo 未完成 真人本地链曾推进到拍照与质检回环；不间断 S1→S6 整链与机器人巡航交付未完成

技术栈（探月 MVP）

Python 3.11 + FastAPI · React + Vite · Qwen-Omni Realtime · OpenCV · PyAudio + AEC · Supabase · segno 二维码

现场部署形态

主机跑后端 `:8000` + 前端 `:8080/flow/`；浏览器 kiosk 全屏；可选 SSH 端口转发远程看同一界面。

占位未做满的能力

手机拍摄逻辑占位、录像暂按拍照处理、导航粗定位与现场打印/递照片为加分项，未进 MVP 闭环。

Previous Attempt

为何探月未完成真机闭环

事实口径（不再反复确认）

PhotoMate 在探月计划 · Physical AI 黑客松期间未完成完整真机 Demo。直接原因是赞助商本体未向参赛项目开放导航、机械臂/灵巧手等执行权限，感知—交互—拍摄软件链无法接到真实机器人动作上。

当时实际沉淀：产品与流程设计、五层软件架构、拍照 Agent 状态机与前后端、本机设备与 Omni 联调、部分硬件/外设方案。文档里完整「巡航→点快门→递照片」多为设计目标，不能表述为已全部完成。

方案按「能力接口—任务状态—本体适配」设计，不依赖银河通用。星尘 Astribot OS 的能力包、应用编排与真机开发支持，适合把同一体验重新做成可运行的机器人 App / 半解决方案。
